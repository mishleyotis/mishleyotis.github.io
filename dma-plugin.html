The 47-agent assessment plugin

The multi-agent system that produces the assessments DMA Insights publishes. Forty-seven agents in eleven families, six skills, and sixty-five gates that decide whether a page is allowed to reach a client, all packaged as one installable Claude plugin.

Role
Architect and sole maintainer
Serves
DMA Insights, in production
Contains
47 agents, 6 skills, 2 commands, 5 hooks
Connector
33 tools, 65 publish gates

The problem

One monolithic producer re-produced six pages to fix one card.

The first version generated a whole assessment in one pass. When a reviewer flagged a single card on a single page, the only available response was to run the whole thing again, which changed five other pages nobody had asked about.

Reviews became unrepeatable. That is not a prompt problem, and no amount of instruction fixed it.

The approach

Make production cheap. Make checking expensive.

Producers own specific sections of the payload and run on the fast model tier. Checkers, the consolidator, and the quality assurance overseer run on the strong tier and are allowed to refuse, because checking is where depth pays.

Every agent carries an explicit tool allow-list. Capability is declared, not inherited.

The pipeline

Six stages, and none of them optional.

Each stage can stop the run. The value is not in the sequence, it is in the fact that no stage can be skipped by an agent in a hurry.

Stage one
Route
A routing table decides which agent owns the change. Nothing is re-produced by default.
Stage two
Produce
Producers write only the payload sections they own, on the fast model tier.
Stage three
Challenge
A challenger, an evidence integrity checker, and a numeric reconciliation checker attack the output.
Stage four
Consolidate
The consolidator refuses unchallenged input. Skipping stage three is not an available shortcut.
Stage five
Submit
One agent submits and promotes. Content enters through the connector in exactly one place.
Stage six
Learn
The overseer writes the findings memory, so the same refusal is not discovered twice.
Hooks refuse doomed work early

A submit precheck stops a payload before the network call is made. A verdict watcher writes to the memory when a gate refuses the same thing twice.

Gates that explain themselves

All sixty-five gates carry producer guidance, so a refusal says what to do differently. A test refuses to let a new gate ship without it.

Golden cases, replayed

Sparse evidence, contradictory evidence, dependency caps, staleness, and critic passes are held as fixed cases and replayed before a change ships.

What it taught me

Two findings worth more than the feature work.

Finding one

Two credentials that fail identically

Most install failures were one of two missing credentials, and both presented the same way: the connector's tools were simply absent, and absent carries no reason. A path token proves which connector you meant. An identity token proves who you are.

A doctor command now names the missing one instead of leaving an engineer to infer it from an empty tool list.

Finding two

A token that is sent is not a token that is checked

The connector granted invoker access to all users with open ingress. The plugin minted an identity token on every connection, sent it, and nothing on the other side ever read it. Authentication rested entirely on a thirty-two character token in a web address, on the one component permitted to write serving content.

Every check passed throughout, because each measured that a credential existed and none measured that anything enforced it. The doctor now probes enforcement directly with an unauthenticated call to a deliberately wrong token.

Outcome

Fixing one card no longer re-produces six pages.

The plugin now backs 100+ digital maturity assessments delivered across the nine financial services subverticals, under approval-gated, standards-aligned review.

Consolidating the knowledge graph from 326 files into 25 bundled ones is what made it installable in the first place.
