Capability agent

Capability Intelligence Agent

Ask the catalogue a question in plain language.

Queries resolve against the curated taxonomy rather than a vector index, so every answer arrives with the catalogue entry that justifies it: pillar, category, capability, subcapability.

The question
Do we cover real-time payments for credit unions, and how deep does it go?
The answer, with its catalogue path
Catalogue version 2.4

Covered, to subcapability depth. The capability sits under payments within the customer-facing pillar, and carries the five diagnostic facets every subcapability carries, so an assessment can score it rather than assert it.

Answers never travel without their path. If a question resolves to no entry, the agent says so instead of assembling a plausible one.

Pillar›Category›Capability›Subcapability
Four levels, held separately on purpose. Collapsing two of them is how a catalogue starts drifting.
Level one
Pillar
Four domains. Stable, and deliberately few.
Level two
Category
Areas of work a team can own.
Level three
Capability
The unit a proposal is scoped against.
Level four
Subcapability
Where evidence attaches, on five diagnostic facets.
Why it is built this way

The constraint is the feature. A retrieval layer that can only answer from catalogue entries cannot invent a capability the firm does not have, which is exactly the failure mode that makes a scoping conversation expensive.
