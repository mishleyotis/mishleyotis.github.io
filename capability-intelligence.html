Capability Intelligence Agent

A conversational surface over the firm's capability catalogue, four levels deep across four pillars. Ask it a question in plain language and it answers from a curated taxonomy, with the catalogue entry that justifies the answer attached.

Role
Sole engineer, end to end
Users
Solution architects and delivery leads
Depth
Four pillars, four levels
Runs on
Google Cloud Run

The problem

A capability catalogue nobody can query is a spreadsheet nobody opens.

The catalogue holds the firm's view of what it can do, broken down four levels deep across four pillars. It is the reference for scoping, for assessment, and for answering a client asking whether a capability is covered.

In spreadsheet form, finding the right entry took knowing the taxonomy first. The people who most needed it were the least likely to have that in their head.

The approach

Retrieval over a curated graph, not a similarity guess.

Queries resolve against the catalogue's own structure. A question about a capability lands on a specific subcapability, and the answer carries its pillar, category, and level with it.

That constraint is the feature. An answer that cannot be traced to a catalogue entry is not an answer this system is allowed to give.

The build

Three layers, one conversation.

Surface

A query interface, not a chatbot

Built in React and TypeScript. Answers arrive with their taxonomy path visible, so a user learns the structure by using it rather than by reading a legend first.

Retrieval

Subcapability matching against the catalogue

A query builder narrows to the pillar and category before it looks at entries, so a broad question does not return a long list of near misses.

Data

PostgreSQL, with a versioned catalogue

Version 2.4 is live and version 1.0 is retained and marked inactive. A migration moved subcapabilities to a unified five-facet diagnostic structure.

The catalogue

Four levels, and the discipline to keep them separate.

Each level answers a different question. Collapsing two of them is how a catalogue starts drifting, and drift is what makes it untrustworthy.

Level one
Pillar
The four broad domains the firm delivers in. Stable, and deliberately few.
Level two
Category
How a pillar divides into areas of work a team can actually own.
Level three
Capability
The unit a client recognises and a proposal can be scoped against.
Level four
Subcapability
Where evidence attaches, on a unified five-facet diagnostic structure.

What changed

Scoping conversations stopped starting with a spreadsheet.

The runtime module was replaced with a canonical eight-case implementation, and subcapability schemas migrated to a single five-facet diagnostic structure. Two changes that sound like housekeeping and were the difference between a catalogue and a queryable one.

The same catalogue now feeds the assessment skills used in DMA Insights.
